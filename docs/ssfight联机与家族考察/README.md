## 0. 先回答三个问题

### 0.1 这个版本有多少联机内容？

有，而且成体系，但全部是**异步联机**：

| 类别 | 内容 |
|---|---|
| 账号/会话 | UC 统一登录、`ssid`、Cookie 会话、2 分钟状态轮询 |
| 社交 | 好友、随机对手、添加/验证/删除/推荐/邀请、玩家档案、留言板 |
| 师徒 | 收徒、逐出、退出师门、徒弟加油、日贡 |
| 异步 1v1 | 挑战好友/随机对手、切磋、关卡、战报回放、复仇 |
| 竞技场 | 4 人两轮淘汰，10 秒轮询出结果 |
| 天梯 | 攻/防排名、每日 30 场（客户端）、金杯、积分、周奖励、复仇 |
| 家园房间 | 金松果赌局：开房、随机进房、2 骰比大小、抽成、金松果榜/胜场榜 |
| 征战 | 4 人组队打 BOSS，10 秒轮询，掷骰分奖 |
| 消息 | 战斗消息、好友验证、留言、征战消息、天梯战报 |
| 排行 | 天梯榜、活动榜、金松果榜、胜场榜、同级伤害榜 |
| 平台 | UC VIP/U 点、充值、抽奖、投票/颁奖 WAP 页、论坛、反馈 |
| 家族 | **服务端协议面存在，客户端没有入口**（详见第 4 节与 `02-家族公会专题.md`） |

**明确不存在的**：实时 PvP、聊天/私聊、世界频道、交易/拍卖、带附件的邮件、观战、在线状态、公会（客户端）。

### 0.2 有没有公会？

要分三层回答：

1. **客户端：没有。** 4551 个反编译 `.as`、主 SWF、HTML5 整包、FLA 里都搜不到 `家族`/`公会`/`Family`/`Guild`；没有家族界面、没有家族按钮、没有 `loadFamily.do` 调用。
2. **服务端协议面：有，名字叫“家族”（family）。** 第三方辅助工具 `UC松战辅助.exe` 里有完整的家族解析器和 URL：
   - `loadFamily.do` → `hasFamily / familyId / name / exp / nextExp / amount / capacity / prestige / chairManName / declaration / persisDevote`
   - `loadMembers.do` → `<member playerId position perWeekDevote>`，职位是**族长 / 副族长 / 护法 / 族员**
   - `fightFamily.do?targetId=`（家族战/对抗）
   - 家族日志 / 战事日志、家族任务、家族商店（1~5 级，消耗“贡献”）
3. **可玩性：这份包里玩不到。** 没有抓到任何家族请求/响应；`player.do` 的存档 XML 里也没有家族字段；辅助工具只做“查看 + 参战”，没有创建/加入/退出家族的操作。

一句话：**“家族”是原版服务器真实存在的模块，但这份 Flash 客户端没有接入口；它不等于“原版完全没有公会”，也不等于“客户端有公会”。**

### 0.3 它是实时联机吗？

**不是。** 没有任何 `XMLSocket` / `NetConnection` / `LocalConnection` / `SharedObject` / WebSocket。所有请求都是 HTTP GET，响应是 XML；战斗由服务器算完，客户端只负责解析和播放回合流水。对手不需要在线，所谓“匹配”是服务器从已报名/已有快照的玩家里凑人。

## 2. 架构一句话

```
[Flash 客户端]
   │  HTTP GET  baseUrl + "flash/xxx.do?..." + "&order=N"
   ▼
[FightGame 服务端]  ── 算战斗、算掉落、算排名、存关系
   │  text/xml; charset=utf-8
   ▼
<resp errorCode="0" ...> ... </resp>
   │
   ▼
[客户端] 只做：解析 XML → 播放服务器给的回合流水 → 填 UI
```

关键点：

- `baseUrl` 硬编码为 `http://ssfight.u.uc.cn/FightGame/`（`MainMovie.as:19612`）。
- `HttpSender` 是单例 + 全局 FIFO 队列，每个请求自动追加 `order=N`；同一时刻只发一个请求（`ActionScript/HttpSender.as`）。
- 响应统一 `<resp errorCode="0" msg="...">`；`errorCode == 10` 走掉线/重连，`errorCode == 31` 被静默忽略。
- `check.do` 每 **120 秒**轮询一次；竞技场/征战每 **10 秒**轮询一次。
- 没有服务器主动推送；“跑马灯/喜报”靠 `login.do` / `check.do` 响应里的 `push_message` 和 `goodnews` 节点捎带。
- 战斗完全服务器权威：`fightParse()` 解析 25 字段的回合日志，客户端不算伤害、不算命中、不算先手。

### 4.4 和“师徒”不是一回事

师徒是**两个人**的关系：收徒、逐出、退师门、徒弟加油、日贡；它没有家族 ID、没有成员列表、没有家族商店。家族是**组织**：有 ID、等级、人数上限、威望、职位、贡献、日志、家族战。两者都用了“贡献”这个词，但师徒的“贡献”是日贡经验（`text4725`），家族的“贡献”是商店货币（数据表 A29-A33），不要混。

### 4.5 9game 的“公会”是平台外链

抓包里的 9game 游戏详情页有一个“公会”按钮，指向 `gh.9game.cn/SearchList.Htm?...KeyWord=515129`。这是**九游平台自己的公会系统**，不是游戏内的家族，也没有任何游戏协议字段。搜索“公会”只命中这一处。

## 5. 与现有文档/实现的关系

### 5.1 对 `docs/经典模式-可行性.md` 的补充

该文档说“原版**没有**……聊天、公会”（`:17`），并在能力表里写“成就 / 公会……全部不存在”（`:493`）。就**客户端界面**而言，这个结论成立；但本次在辅助工具和策划表里发现了服务端的家族模块。建议把口径改成：

> 原版客户端没有家族/公会入口；服务端协议面存在“家族”模块（信息/成员/任务/家族战/家族商店），但本包没有抓到响应，也没有创建/加入流程。

这不是推翻原结论，而是把“客户端没有”和“服务端没有”分开。

### 5.2 对 `docs/联机实现方案.md` 的补充

该文档 §1.3 已经指出“原版的‘房间’是骰子，不是对战房间”，本次用 `pubDesArray`（`MainMovie.as:19568`）和 `openRoom/played` 的代码路径再次确认。本报告新增的是：

- 家族模块的字段与证据；
- 真实抓包只覆盖大厅接口，战斗协议是代码反推；
- 好友/师徒/竞技场/征战/房间的完整接口与轮询节奏。

### 5.3 当前联机版有没有家族？

没有。当前服务端只有 `server/api/social.js`（消息/好友/留言/论坛）、`campaign.js`（征战）、`ladder.js`（天梯）、`forum.js`（论坛），没有家族表、家族动作或家族 UI。`shared/actions.json` 也没有家族动作。若要做，应把它当作**按原版字段重建的新设计**，不要声称“还原原版家族规则”——原版的创建/加入/贡献/家族战规则并没有留下来。

## 7. 证据强度与缺口（先看，避免过度引用）

1. **战斗协议不是抓包。** 18 份战斗响应是按 `fightParse()` 的字段生成的；真实抓包只有大厅接口。协议字段本身来自客户端代码，强度 A；服务端真实返回长什么样，强度 B/C。
2. **`config.xml` / `config1.xml` 没抓到。** 两次都是 304、0 字节；服务端权威数值缺失，客户端内嵌表只是兜底。
3. **家族没有响应样本。** 只有辅助工具的解析器字符串，没有一条真实 XML；字段名可信，字段取值/嵌套/错误码未知。
4. **辅助工具是第三方。** `UC松战辅助.exe` 与官方无授权关系，字符串可能不完整、可能有作者自己的理解；只当协议字典用。
5. **客户端版本。** 客户端含 `activity_2013NewYear`（`MainMovie.as:640`），不是最早期的 2012 版；但家族入口仍然没有。可能是家族只存在于更晚的客户端/网页端，或只对部分服开放——没有证据，不能下定论。
6. **没有服务端代码。** 所有“服务端有”的判断都来自客户端调用、辅助工具解析器和数据表，不是服务端源码。

## 8. 一句话给实现者

> 这份参考包能告诉你“原版联机长什么样、字段怎么摆、轮询多快、战斗谁说了算”，但不能告诉你“家族怎么创建、贡献怎么算、家族战怎么匹配”。家族部分尤其如此：**字段是真实的，规则是缺失的。**
