# 家族/公会专题

> 结论先行：**这份客户端没有家族/公会入口；但原版服务端确实有一个叫“家族（family）”的模块。**
> 证据来自第三方辅助工具 `UC松战辅助.exe` 的响应解析器、`松鼠数据表.xlsx` 的家族商店，以及客户端/抓包里的“零命中”负证据。
> 证据分级：A 代码/抓包；B 二进制字符串/数据表；C 推断；D 未知。

---

## 1. 三层结论

| 层 | 结论 | 依据 |
|---|---|---|
| **客户端** | 没有家族界面、没有家族按钮、没有 `loadFamily.do` 调用 | 4551 个 `.as`、主 SWF、HTML5 整包、FLA 全部 0 命中（A，负证据） |
| **服务端协议面** | 有 `loadFamily.do` / `loadMembers.do` / `fightFamily.do` / `loadLog.do`；有家族等级、人数上限、威望、族长、宣言、贡献、职位、家族战、家族商店 | 辅助工具解析器 + 数据表（B） |
| **可玩性** | 这份参考包里玩不到；没有创建/加入/退出/捐献协议，没有响应样本，没有 UI | 客户端 0 调用 + 抓包 0 家族请求（A/B） |

所以：

- 说“原版完全没有公会”**不准确**——服务端有家族模块；
- 说“原版有公会玩法”**也不准确**——至少这份客户端没有入口，规则也大量缺失；
- 准确说法：**“原版服务端有家族模块，这份客户端没有接；家族的可玩规则大部分没有留下。”**

## 3. 家族数据模型（从字符串还原）

### 3.1 家族主体

`loadFamily.do` 的响应属性（按辅助工具解析顺序）：

| 字段 | 类型 | 含义 | 置信度 |
|---|---|---|---|
| `hasFamily` | bool | 是否已加入家族 | 高 |
| `persisDevote` | int | 个人累计贡献（“persistent devote”） | 高 |
| `familyId` | int | 家族 ID | 高 |
| `name` | string | 家族名 | 高 |
| `exp` | int | 家族经验 | 高 |
| `nextExp` | int | 升级所需经验 | 高 |
| `amount` | int | 当前成员数 | 高 |
| `capacity` | int | 成员上限 | 高 |
| `prestige` | int | 家族威望 | 高 |
| `chairManName` | string | 族长名 | 高 |
| `declaration` | string | 家族宣言 | 高 |

辅助工具在这些字段之后显示：

```
)                  威望:
(  LV
家族:
你尚未加入任何家族!
```

可推断 UI 是：“家族：[名称]（[等级] LV） 威望：[值]” + 成员数/上限 + 族长/宣言；未加入时显示“你尚未加入任何家族!”。

### 3.2 成员

`loadMembers.do` 的响应节点：

```xml
<member uc... playerId="..." position="..." perWeekDevote="..."/>
```

| 字段 | 含义 | 置信度 |
|---|---|---|
| `playerId` | 玩家 ID | 高 |
| `position` | 职位 | 高 |
| `perWeekDevote` | 本周贡献 | 高 |
| `uc...` | 可能是 `ucId` / `ucName`（字符串被截断） | 中 |

职位四个值（辅助工具 UI 直接列出）：

```
族长
副族长
护法
族员
```

### 3.3 贡献体系

| 字段 | 范围 | 用途 |
|---|---|---|
| `persisDevote` | 个人累计 | 家族信息页展示；可能用于职位/权限 |
| `perWeekDevote` | 个人本周 | 成员列表展示；可能用于周结算/家族任务 |
| 家族商店“贡献消耗” | 12/25/25/25/30 | 在家族商店消费 |

贡献的**产出方式**没有证据。合理推测是家族任务/家族战，但没有任何数值或接口能证明，不能写成结论。

### 3.4 一个可用的最小模型（重建用，不是原版）

```sql
families(
  id, name, leader_id, level, exp, prestige, declaration,
  capacity, created_at
)
family_members(
  family_id, account_id, position, week_devote, total_devote, joined_at
)
family_logs(
  id, family_id, kind, text, created_at
)
family_shop(
  level, item_id, cost_devote
)
```

这张模型只覆盖“已知字段”；创建/加入/退出/解散/转让/家族战匹配/奖励都没有原版依据。

## 4. 家族功能面

### 4.1 家族信息页

辅助工具会显示：

- 家族 ID
- 族长
- 人数（`amount` / `capacity`）
- 威望（`prestige`）
- 家族等级/经验（`exp` / `nextExp`）
- 宣言（`declaration`）
- 个人累计贡献（`persisDevote`）

未加入时显示“你尚未加入任何家族!”。

### 4.2 成员列表

- 职位：族长 / 副族长 / 护法 / 族员
- 昵称
- 周贡献（`perWeekDevote`）
- 可能还有“出战”状态（字符串 `----|出战|.` 紧跟在成员解析之后，但也可能属于幻兽；**不作为结论**）

### 4.3 家族任务

辅助工具的表头/按钮：

```
家族任务
参与
条件
描述
操作日志
```

这说明家族任务至少有：条件、描述、参与按钮、操作日志。但没有任何任务列表字段、奖励、次数、刷新规则。`tasks.do` 是辅助工具里唯一像“任务”的接口（`gained="`），客户端未调用；它可能是家族任务，也可能是日常任务，**不能确认**。

### 4.4 家族战/对抗

接口：

```
FightGame/flash/fightFamily.do?targetId=
```

辅助工具把它和 `fight.do?targetId=` 放在同一段，说明它返回的也是 `combat` 结构（查看器甚至为它生成了胜/负两份战斗 stub）。可确认：

- 家族战是**按 targetId 打某个对手**；
- 返回战斗流水，客户端/工具播放；
- 但匹配方式、目标范围（敌对家族/同族切磋）、积分、奖励、次数全未知。

辅助工具还写了：

```
对抗BOSS-功能尚未开放
对抗
```

这只说明**该辅助工具那个版本**里这个入口没开放；“对抗”可能是家族战的页签。⚠ 但 2013-09-12 官方公告明确写了「每周不定期将有精英BOSS侵入家族」，2013-10/11 的攻略也有家族 BOSS 打法（[公告](https://www.9game.cn/ssdzflash/125591.html)、[攻略](https://www.gamedog.cn/songshudazhan/gl289044.html)），所以不能把辅助工具这句话当成“原版没有家族 BOSS”。

### 4.5 家族日志 / 战事日志

辅助工具的消息中心有四个页签：

```
家族日志
战事日志
留言板
好友验证
```

对应接口很可能是：

```
loadLog.do?logType=0   → 家族日志
loadLog.do?logType=1   → 战事日志
messages.do?type=4     → 留言板
messages.do?type=3     → 好友验证
```

这是**高置信推断**（页签顺序与接口顺序一致），但没有响应样本，不能 100% 确认。

### 4.6 家族商店

数据表已给出 5 级商品（见 2.2）。可确认：

- 家族等级 ≥ 商品要求才能买；
- 消耗“贡献”；
- 商品进入背包/装备体系。

未知：商店在哪打开、是否限购、是否每周刷新、贡献是否可交易。

### 4.7 家族 BOSS

辅助工具里有一句“对抗BOSS-功能尚未开放”，但它只代表该工具/该版本的状态，**不能推出原版没有家族 BOSS**：2013-09-12 官方公告明确说“每周不定期将有精英BOSS侵入家族，战胜精英BOSS的家族将获得威望奖励”，2013-10/11 的攻略也详细写了脱装打 BOSS、终结阶段等玩法。原版家族 BOSS 的具体血量/次数/奖励仍无客户端或抓包证据。

| 接口 | 方向 | 已知字段/参数 | 客户端调用 | 辅助工具 | 抓包 | 强度 |
|---|---|---|---|---|---|---|
| `loadFamily.do` | 读 | `hasFamily/persisDevote/familyId/name/exp/nextExp/amount/capacity/prestige/chairManName/declaration` | ❌ | ✅ | ❌ | B |

- 创建家族
- 加入家族
- 退出家族
- 解散家族
- 捐献/建设
- 转让族长
- 任命/撤职
- 家族商店购买

这些字符串在 exe 里 0 命中（`创建家族`/`加入家族`/`退出家族`/`解散`/`捐献`/`建设` 均为 0）。所以**不能把辅助工具当成完整的家族客户端**。

## 6. 为什么客户端没有？

### 6.1 不是“有界面但没接线”

客户端里连“家族”两个字的资源都没有：SWF 文本、SVG、FLA、HTML5 整包、导出符号全部 0 命中。所以不是“入口被隐藏/按钮没接”，而是**这个构建根本没有家族 UI**。

### 6.2 版本时间线

- 客户端代码含 `activity_2013NewYear`（`MainMovie.as:640`），说明构建时间不早于 2012 年底/2013 年初。
- 抓包响应里出现过 2013-07 的 9game 图片路径；整体跨 2012~2013。
- 客户端仍然没有家族。
- **2013-09-12 九游官方更新公告开放家族系统**：20 级村庄出现「家族」入口、50 级可创建；家族任务给个人贡献/家族经验/威望；家族升级解锁人数与护法上限、福利；每周有精英 BOSS 入侵（[公告原文](https://www.9game.cn/ssdzflash/125591.html)）。这个时间**晚于**本包的构建与抓包（2012~2013-07），所以本包没有家族 UI/资源是符合时间线的 —— 不只是"有界面没接线"，而是这份构建早于家族上线。

所以更准确的解释是：**家族是 2013-09 之后才上线的功能，本包是上线前的构建**。后来家族 UI 具体长什么样，这份包里没有，不能拿它当原版依据；也不排除家族只对部分服/渠道开放、或属于《松鼠大战2》等后续分支。

> 2026-11 用户提供的家族大厅截图（页签「大厅 / 任务 / 族员 / 福利 / 战事」，活动「镖行天下」周三、周五 9:00-24:00）**不在这份包里**：客户端、资源、数据表、辅助工具全部 0 命中；它显然属于家族上线后的版本（也可能是《松鼠大战2》/其他分支），现有材料无法确认具体版本，更不能把「镖行天下」的规则当成原版规则。

### 6.3 辅助工具的作者为什么知道？

辅助工具是第三方外挂/助手，作者显然抓过包或逆向过服务端协议。它实现了 `loadFamily`/`loadMembers`/`fightFamily` 的解析，说明当时服务器上这些接口是**可用**的（至少对某些账号）。但它没有实现创建/加入，可能是因为：

- 这些操作在网页端；
- 或者作者没做；
- 或者接口需要额外权限/参数，作者没拿到。

无论哪种，都说明“服务端有家族数据”，但不说明“客户端能玩家族”。

## 7. 家族不是什么

| 容易混淆的 | 实际是什么 | 区别 |
|---|---|---|
| 师徒 | 两人关系：收徒/逐出/退师门/日贡/加油 | 没有家族 ID、成员列表、职位、家族商店 |
| 好友 | 社交关系：添加/验证/删除/邀请 | 没有组织、等级、贡献 |
| 房间 | 家园里的 1v1 骰子赌局 | 两人、临时、无组织 |
| 征战 | 4 人临时组队打 BOSS | 临时队伍、无组织、无贡献 |
| 9game 公会 | 九游平台外链 | 平台功能，不是游戏内家族 |

## 8. 如果要复刻：建议与风险

### 8.1 可以“按字段重建”的部分

- 家族主体：`familyId/name/level/exp/prestige/declaration/capacity`
- 成员：`position/weekDevote/totalDevote`
- 职位：族长/副族长/护法/族员
- 家族商店：5 级、贡献货币、5 个商品
- 家族日志/战事日志：两类日志
- 家族战：按 `targetId` 打一场，返回战斗流水

### 8.2 必须自己设计的部分（原版没有留下）

| 设计项 | 可选方案 | 风险 |
|---|---|---|
| 创建条件/费用 | 等级 + 金松果 | 原版未知 |
| 加入方式 | 申请/邀请/直接加入 | 原版未知 |
| 人数上限曲线 | 10/20/30/40/50 | `capacity` 字段存在，但曲线未知 |
| 家族等级经验 | 任务/战/捐献 | 原版未知 |
| 贡献产出 | 家族任务/家族战/每日签到 | 原版未知 |
| 家族战匹配 | 同等级/同人数/积分 | 原版未知 |
| 家族战奖励 | 贡献/威望/金松果 | 原版未知 |
| 家族 BOSS | 原版明确“未开放” | 不要声称还原 |
| 家族商店限购/刷新 | 每周/每月 | 原版未知 |

### 8.3 与当前联机版的衔接

当前服务端没有家族表/动作/UI；如果要做，建议：

1. 在 `server/db.js` 加 `families` / `family_members` / `family_logs` / `family_shop` 四张表；
2. 在 `shared/actions.json` 加 `family.create/join/leave/kick/appoint/donate/task/claim/war`，全部 `async`（有随机/校验）；
3. 在 `server/api/social.js` 或新 `family.js` 里实现；
4. UI 入口优先放“家园”或主菜单，复用经典界面的列表/按钮元件；
5. 经济上只发贡献/威望，不直接发金松果，避免小号转移；
6. 文案里不要写“原版家族规则”，写“按原版字段重建”。

### 8.4 一句话

> 家族是“**字段可考、规则不可考**”的模块。能还原的是数据形状和 UI 骨架；不能还原的是创建/加入/贡献/家族战的具体规则。

## 11. 未解问题（按重要性）

1. **家族怎么创建/加入/退出？** 客户端和辅助工具都没有；可能在网页端或更晚的客户端。
2. **贡献怎么获得？** 家族任务给多少？家族战给多少？有没有每日上限？

4. **家族战怎么匹配/结算？** `fightFamily.do?targetId=` 只说明“打谁”，不说明“怎么配、赢了给什么”。

8. **有没有更晚的客户端带家族 UI？** 本包没有；`h_23650.swf`（3.2 MB，主程序 `version="h"`）也没有。
