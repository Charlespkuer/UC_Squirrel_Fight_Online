## 1. 网络层

### 1.1 启动序列

`MainMovie.as:19093` 的 `startGame()`：

```
getPlayInfo()             → login.do（带 ssid，仅 devMod==0）
getFriends("random")      → randomfriends.do
getFriends()              → friends.do
updateInfo(requestEndCallBack) → check.do
```

`requestEndCallBack` 里才 `setInterval(updateInfo, 120000)`，并进入主界面。也就是说：**登录 → 随机对手 → 好友 → 状态检查** 是进入游戏的四步；任何一步失败都会卡在 loading/错误页。

### 1.2 `HttpSender`：单队列、串行、带序号

`ActionScript/HttpSender.as`：

- 单例，`_urlArray` 是 FIFO 队列。
- `send(url, cb)` 自动追加 `&order=N`（已有 `?`）或 `?order=N`（没有 `?`），`N` 来自全局 `getOrder()`。
- 用 `LoadVars.load(url)` 发 **GET**，`onData` 收到后 `XML.parseXML`。
- `dataCheck()` 要求根节点必须是 `resp`，否则 `connectError(1)`。
- `errorCode == "10"` → `connectError()`（掉线/重连）；`errorCode == "31"` → 静默丢弃；其它交给回调。
- 同一时刻只发一个请求；上一个完成才发下一个。没有并发、没有超时重试、没有取消（只有 `closeLoad()` 清空队列）。

抓包里的 `order=0/2/3` 就是这条队列的序号；它不是会话令牌，也不参与业务校验。

| 轮询 | 间隔 | 代码 |

### 1.5 服务器权威战斗

`fightParse()`（约 `MainMovie.as:17730`）解析服务端下发的：

```xml
<resp errorCode="0">
  <combat winner="0|1" id="..." maxRounds="60" flashProp="0:0|0:0|0:0">
    <attacker playerId name vip level maxHp headHp remainEnergy wears bringPets>
      <master id name level/>
    </attacker>
    <defender ...>...</defender>
    <log>attack,attackType,weaponSkillId,harm,defenseType,...|...</log>
  </combat>
  <fightReward exp="..." trigger="false" prop="0:0" .../>
  <levelReward hp="..." agility="..." power="..." speed="..." .../>
  <deadmanRecord handDamage="..." .../>
</resp>
```

- `log` 每行 25 个字段，`|` 分回合、`,` 分字段。
- `winner` 是**攻击方视角**；玩家当防守方时客户端会翻转（`MainMovie.as:17826-17832`）。
- 客户端只做：切分 25 字段 → 播动画 → 填伤害数字。**不算伤害、不算命中、不算先手、不算暴击。**
- 回合上限 60（`maxRounds=60`）。
- `fightType` 决定走哪条结算/回放分支：

| `fightType` | 场景 | 入口 |
|---|---|---|
| 0 | 挑战好友/随机对手 | `fight.do?targetId=` |
| 1 | 新手引导战斗 | `fight.do?targetId=300` |
| 2 | 收徒（挑战对方师傅/本人） | `recruit.do?targetId=` |
| 3 | 从消息里收徒 | `recruit.do?targetId=` |
| 4 | 看单场回放 | `viewCombat.do?id=` |
| 5 | 挑战 NPC | `challenge.do?npcId=60` |
| 6 | 关卡 | `stage.do` |
| 7 | 竞技场 | `joinArena.do` / `checkArena.do` |
| 8 | 切磋 | `exercise.do` |
| 9 | 天梯 | `rank.do` / `grand.do` |
| 10 | 看整轮战报 | `viewCombats.do` |
| 11 | 复仇 | `revenge.do` |
| 12 | 征战 | `joinCopy.do` |

### 1.6 XML 约定与编码

- `Content-Type: text/xml; charset=utf-8`，`Transfer-Encoding: chunked`。
- 统一根节点 `<resp errorCode="0" msg="...">`。
- 数组用分隔符硬编码，没有 JSON：

| 分隔符 | 用途 | 例子 |
|---|---|---|
| `\|` | 记录之间 | `players="id:name:level:0:0:0\|..."` |
| `:` | 字段之间 | `wears="62:17:1:16:1:0:0;..."` |
| `;` | 装备/穿戴之间 | `wears="62:17:1:16:1:0:0;65:5:...;"` |
| `,` | 子字段 | `state="0,0,0,0,0,0"` |

- `errorCode` 常见：`0` 成功；`10` 掉线；`20`/`23`/`24`/`25`/`27`/`29`/`31`/`32` 是业务错误（不同接口含义不同，客户端按分支弹提示）。
- 请求参数全部走 URL query，没有 POST body（SSO 登录除外）。

## 4. 师徒

### 4.1 规则（数据表 §其他）

- 10 级以下最多 1 个徒弟；10~19 级 2 个；20 级以上 3 个。
- 收徒要打败对方的师傅；对方没有师傅则打败本人；挑战一次花 10 金松果。
- 师傅逐出徒弟：1 天 1 次；徒弟退出师门：20 金松果。
- 徒弟日贡：主动挑战好友/随机好友/关卡经验的 **10%**，主动打经验竞技场经验的 **5%**；徒弟经验不扣；师傅第二天首次登录显示。
- 徒弟为师傅加油：师傅随机获得三属性 **5%** 加成，不同徒弟可叠加，最高 **15%**；只在主动战斗生效，被动无效；战斗面板不显示。

### 4.2 接口

| 接口 | 用途 | 参数 | 证据 |
|---|---|---|---|
| `recruit.do` | 收徒（打对方师傅/本人） | `targetId=` | `MainMovie.as:3154` |
| `eject.do` | 逐出师门 | `id=` | `MainMovie.as:3195` |
| `resign.do` | 退出师门 | — | `MainMovie.as:3226` |
| `fighting.do` | 为师父加油 | — | `MainMovie.as:3249` |

注意：`fighting.do` **不是战斗**，是“加油”。真正的收徒战斗走 `recruit.do` → 返回 `combat` → `fightType=2/3` 播放。

### 4.3 与家族的区别

师徒是两人关系，没有家族 ID、成员列表、职位、家族商店。家族是组织（见 `02-家族公会专题.md`）。两者都用“贡献”一词，但师徒的贡献是日贡经验，家族的贡献是商店货币。

## 6. 竞技场（4 人两轮淘汰）

### 6.1 流程

1. 玩家点“竞技场” → `joinArena.do?useProp=<0/1/2>`。
2. 服务端返回 `status`：
   - `0`：还在匹配，客户端 `setInterval(checkArena, 10000)`；
   - `1`：匹配成功，返回 `group players="..."` + `combat1..combat4`；
   - `2`：匹配失败。
3. 客户端播自己的那场，播完显示名次/奖励。
4. `gainReward.do?arenaMode=` 领奖。

### 6.2 规则/数值

- 11 级经验竞技场；20 级碎片竞技场；30 级天梯赛（数据表 §关卡和竞技）。
- 4 人参赛，两两半决赛，胜者争冠亚、败者争季军（`text7557`）。
- 报名消耗：30 体力，或英雄帖/勇气勋章/召唤证（道具 36/39/82）。
- 奖励（`text7557`）：冠军 150 经验 / 8 蓝碎片 / 40 孵化点；亚军 100/6/35；季军 50/4/30；殿军 30/3/25。
- 抓包 `竞技场/065` 是真实样本：`group players="id:name:level:...|"` 4 人 + `combat1..combat4`，每场都有 `attacker/defender/log`。

### 6.3 证据

`MainMovie.as:3319`（10 秒轮询）、`:3376`（joinArena）、`:3408`（checkArena）、`:3411`（parseRounds）、`:5225`（gainReward）；抓包 `竞技场/065`、`竞技场/092`。

## 7. 天梯

### 7.1 流程

1. `rank.do`：服务端匹配对手，返回 `attackRank` / `defendRank`、`joinRankCount`、`oiling`（徒弟加油）、`expReward`、`reward(gainCup/gainIntegral/robbed)`、`combat1..combat3`。
2. 客户端播 3 场（或按服务端给的场次），结算积分/金杯。
3. `rankList.do` 看排行榜；`grand.do` / `grandList.do` 是活动/大奖赛入口与榜单。
4. 被抢金杯后可 `revenge.do` 复仇（当天有效）。

### 7.2 规则/数值（数据表 §关卡和竞技）

- 30 级开放；每 10 级一个赛区。
- 数据表写「每天最多 20 场；前 10 场免费，后 10 场每场 5 金松果」；**客户端 `alertRank()` 实际按 30 场拦**：1-10 免费、11-20 每场 5、21-30 每场 10 金松果（`MainMovie.as:23720-23760`）。两处不一致，按客户端为准。
- 主动参赛：胜 3 金杯、负 1 金杯；主动获胜有几率抢对方 3 金杯。
- 被动参赛获胜不抢金杯；主动参赛失败也不会被抢。
- 积分：胜排名高者 +16；胜排名低者 +15/+2/+1/0（按排名差）。
- 每周前 100 名 50 金杯（`gainRankCup.do`，`MainMovie.as:1878`）。
- 天梯商店：`buyRankGoods.do?id=&count=`。

### 7.3 证据

`MainMovie.as:1833`（rankList）、`:1866`（grandList）、`:1886`（gainRankCup）、`:2970`（rank）、`:2994`（grand）、`:18322`（parseRank）、`:3798`（rankMessages）、`:3895`（revenge）。

## 8. 家园赌局房间（“房间”不是对战房）

### 8.1 玩家看到什么

家园建筑“？”里可以：

- 自己开一局，押 100/500/1000 金松果；
- 随机进别人的局；
- 双方各掷 2 个骰子比大小；
- 赢家拿奖池的 90%，系统抽 10% 手续费；
- 看“金松果榜”和“胜场榜”、开局/挑战记录。

### 8.2 规则（`pubDesArray`，`MainMovie.as:19568`）

1. 自己开局或加入他人的游戏，匹配成功后自动开始。
2. 两人各抛 2 个骰子比大小。
3. 点数大的一方获胜。
4. 点数和相同，单个骰子大的一方获胜。
5. 骰子组合完全一致 → 不分胜负，本金返还，不产生消耗。
6. 自己开的局，自己不能参加。
7. 每次开新局/参加他人局以 1 把为限，无论输赢都结束。
8. 每局结束，系统从双方投注总额中收取一定金松果作为手续费。

代码里 `costLimit * 9 / 10`（`:4676`）就是赢家拿 90%。

| `publist.do` | 金松果榜/胜场榜 | — | `:4568` |

`randomPubRoom.do` 最多返回 4 个房间（`parseRoomFriends`，`:4509`）；房间字段：`roomId/ucId/name/costLimit/createTime/playerId`。

### 8.4 关键限制

这是**异步赌局**：开房后可以离开，等别人来挑战；挑战结果通过“记录”消息查看。不是两个人同时在线掷骰子。

## 9. 征战（4 人组队打 BOSS）

### 9.1 流程

1. 玩家点“征战” → `joinCopy.do?copyId=<bossId>`。
2. 服务端返回 `status`：
   - `0`：匹配中，`setInterval(checkCopy, 10000)`；
   - `1`：开战，返回 `players="id:name:level|..."` + `combats` + `rollDatas`；
   - `2`：匹配失败（“没有找到合适的队友”）。
3. 客户端播战斗，然后播掷骰分奖。
4. `claim.do?key=<msgKey>` 领奖。

### 9.2 规则/字段

- **4 人组队**：`MainMovie.as:12692` 直接写“4人组队战斗，X级以上可报名参加。征战奖品包括高级召唤兽、紫色装备等。”
- 报名消耗 1 个“征战令”（道具 87）；每周二、四、六登录送 1 个，商店也卖（`:5347`）。
- 服务端返回多场 `combats`（按队员各一场的推断），不是共享血量的实时接力。
- 战利品用掷骰：`rollDatas` 每件奖品有 `players`，每人 `point/isMax`；点数最高者得（`:5259-5313`）。
- 征战消息走 `messages.do?type=5`（`:5463`）。
- 匹配失败文案：“匹配失败，没有找到合适的队友，请稍后再试吧！”（`:19594`）。

### 9.3 证据

`MainMovie.as:5354`（joinCopy）、`:5378`（checkCopy）、`:5431`（claim）、`:5228`（parseJoinCopy）、`:12692`（4 人组队文案）。

> 与当前联机版的差异：当前实现是“每名队员分别打满血 BOSS”，原版这里也只能证明“4 人组队 + 各自战斗 + 掷骰分奖”，不能证明共享血量/接力。

## 14. 抓包覆盖：真实 vs 生成

### 14.1 真实抓到响应体的业务接口（8 个）

| 接口 | 抓包样本 | 说明 |
|---|---|---|
| `login.do` | `登陆/001`、`new/022`、`new2/017` | 登录奖励/师徒日贡 |
| `player.do` | `关卡/003`、`竞技场/076` 等 136 次 | 存档 XML |
| `friends.do` | `关卡/004`、`new/023` | 好友列表 |
| `randomfriends.do` | `关卡/005`、`辅助关卡/174` | 随机对手 |
| `messages.do` | `关卡/006`、`竞技场/054` | 战斗消息 |
| `check.do` | `new/024`、`new2/019` | 状态/角标 |
| `checkArena.do` | `竞技场/065/087/092` | 4 人竞技场 |
| `levelUp.do` | `关卡/007` | 升级 |

另有 `h.jsp`、`flashindex.jsp` 两个页面响应也是真实抓包。

### 14.2 生成的（不是抓包）

| 内容 | 来源 | 说明 |
|---|---|---|
| 9 个战斗接口 × 胜/负 = 18 份（另有 4 份回放，共 22 个 XML） | `viewer/battle/*.xml` | 按 `fightParse()` 字段生成 |
| `config1.xml` / `config.xml` | 按客户端内嵌表重建 | 真实请求两次都是 304 |
| `rank.do` / `rankList.do` / `grand.do` / `grandList.do` | 按 `parseRank` 重建 | 没有真实响应 |
| `publist` / `openRoom` / `pubRecord` / `played` | 空/生成 | 没有真实响应 |
| `loadFamily.do` / `loadMembers.do` | 61 字节空 `<resp errorCode="0"/>` | 连字段都没填 |

### 14.3 结论

- **大厅/社交**：有真实样本，字段可信。
- **战斗/竞技/征战/天梯/房间**：协议来自客户端代码，**服务端真实返回未被抓到**；字段名可信，取值/嵌套/错误码需要保守对待。
- **家族**：只有辅助工具字符串，**零响应样本**。
