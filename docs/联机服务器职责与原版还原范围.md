# 联机服务器职责与原版还原范围

本说明对应 `E:\Squirrel_Fight_Online` 的 1.0.2 源码（2026-10-27）。
1.0.2 的 Windows EXE 与 Android arm64 APK 已完成构建与下述检查；公网 API 已上线 1.0.2 并启用原生设备绑定策略。
iOS 构建链已准备，但目前没有生成本轮 IPA，具体阻断见末节。

## 1. 联机版与单机版如何分工

- 联机版是独立应用，包标识为 `com.ssdz.online`，不覆盖单机应用或单机存档。
- 客户端内置经典界面、图片、声音与战斗播放器；日常游玩不从服务器下载整套资源。
- 账号进度由服务器保存，客户端只能发送动作意图，不能上传整份存档覆盖权威数据。
- 当前只开放经典界面；单机的现代界面、挑战塔及调试入口不属于本联机版本。经典常规无尽塔与勇者剧本按用户 2026-11 口径开放（村庄右上角小径进入，**20 级解锁**），但**零局外奖励**、对局进度只存本机，不写服务端存档。
- 断网不能继续推进权威进度；异步对战也需要联网提交，不能理解为离线发奖后补传。
- 单机版的数值和随机生成代码得到复用，服务器在独立运行环境中执行它们。

## 2. 服务器完整承担什么

- **账号与会话**：注册、名字及编号、登录、恢复码找回、退出登录与注销账号。
- **设备绑定与审计**：同一设备 / 同一 IP 最多创建 3 个账号（可配置）；同一账号只保留一个在线会话，后登录顶掉旧设备；记录登录来源 IP、变更与拒绝原因，供管理端查询。
- **权威进度**：等级、经验、货币、装备、武技、道具、幻兽、建筑及各类次数。
- **动作校验**：只执行 `shared/actions.json` 白名单动作，检查参数与存档版本。
- **随机决策**：升级、融合、果实候选、敌人、战斗种子及宝箱奖品在服务器产生。
- **战斗计算**：服务器运行共享 `Sim`，决定胜负、回合记录、经验及其它结算。
- **战斗快照**：保存玩家可供挑战的阵容，升级及有效面板变化时更新。
- **匹配与排行**：筛选异步玩家、补充 AI、维护天梯积分、金杯、每日次数和赛季状态。
- **社交与消息**：保存好友关系、留言、战斗消息，以及真人师徒关系、人机拜师、收徒挑战与真人徒弟日供。
- **征战队列**：维护报名、组队、独立战斗、掷骰及奖励领取状态。
- **持久化与重试**：SQLite 保存进度与结算；已实现的战斗幂等及宝箱领取避免重复发奖。
- **运行维护**：Caddy 提供公网入口，Node API 监听本机，systemd 负责服务重启。

主要实现入口是 `server/index.js`、`server/game/`、`server/api/` 和 `server/db.js`。
角色动作通过存档版本检测冲突；这不等于每一个历史接口都具有相同的幂等协议。
界面显示的最近战斗记录与服务端回放、审计账本是不同的数据集合。

## 3. 人少时如何混合玩家与 AI

随机挑战和天梯候选先找合适的当前玩家快照，再尝试历史快照，最后由服务器 AI 补位。
默认一页三个候选；不会为了填满列表把 AI 伪装成真人账号。

- **玩家**：来自真实账号保存的战斗快照。可以异步挑战，不表示对方此刻在线或正在操作。
- **历史快照**：仍是真实玩家的过往阵容，服务端保留 `historical` 标识，不能冒称实时状态。
- **AI**：复用单机的 `State.genAI` 及其装备、武技和幻兽生成逻辑，由服务器固定本次面板。
- 列表用简短的“玩家 / AI”说明来源；玩家还可显示 `名字#编号`，详细说明解释异步性质。
- 候选票据绑定账号、用途与有效期。选中哪个面板，就挑战那个固定战斗体，不在开战时偷换。
- 随机挑战中的 AI 正常消耗体力、结算挑战奖励；天梯 AI 只是免费陪练。
- 天梯陪练不收费、不改积分和金杯、不计每日天梯次数，也不发经济奖励或战后宝箱。
- 添加好友可以随机生成最多 10 位 AI 好友，服务器保存其战斗快照并标注 AI；与 AI 好友免费切磋，不产生奖励或天梯积分。正式玩家天梯结算与好友切磋仍按各自规则处理。
- 好友页提供与单机同规则的测攻击木头人：服务器计算训练并保存总伤害和武器、技能、徒手分项纪录，不产生奖励。

## 4. 哪些地方复用了 ssfight 的界面

参考来源是单机项目的 `references\ssfight`；运行时使用已提取的 `images/ssfight/ui/`。
客户端不依赖参考目录，也没有重新运行原来的 Flash 客户端。

- 挑战主界面复用原版元件 `7638` 及其随机、好友、关卡、竞技等页面帧。
- 对手行复用 `7237` 的名字、等级与选中状态；动作二级页复用 `4756`。
- 征战主容器复用 `3437`，将本服务器的报名、等待与结果填入原有页面结构。
- 战斗演出复用经典播放器与资源，战果页后使用原版 `7771` 四箱翻奖容器。
- 原版 `7251` 表达关系，`7252` 表达 VIP，二者没有被冒用成“真人认证”图标。
- “玩家 / AI”是本项目新增的简短来源文字，沿用经典页面的位置与反馈方式。
- 登录借用原版背景素材，但账号表单、恢复码和联机错误提示是本项目新增内容。
- 设置保留当前经典系统页的布局与通用控件；账号操作是联机扩展，不声称与原版逐像素相同。

## 5. 设置、账号与战后宝箱

声音、画面、跳过按钮及后台运行等偏好保存在本机；“同步进度”重新读取服务器权威状态。设置页显示可搜索的数字玩家 ID，也可使用完整名字#编号添加好友。后台运行受系统资源管理约束，不能保证应用被系统挂起或终止后继续运行。
设置页提供退出登录与注销账号；未领取的战斗宝箱在登录后提示领取。单机导入、导出等会绕过权威进度的操作不在联机版提供。
注销要求当前密码，会撤销会话并清理本人账号数据；他人已结算奖励保持不变，历史关联按需匿名化。

1.0.2 的原生来源为 Windows `MachineGuid`、Android `ANDROID_ID`、iOS 本机 Keychain 持久随机值。
客户端只返回带应用域与平台域的 SHA-256 摘要，不上传原始 OS 标识；服务器再次摘要后保存设备绑定。
同一设备不能注册或绑定另一个仍存在的账号；同一账号允许在其它未绑定账号的设备上登录。
设备读取失败时不悄悄退回临时安装 UUID；旧客户端缺少设备请求头，需要更新后才能继续联网养成。
正式服务器设置 `ALLOW_BROWSER_DEVICES=false`；浏览器弱安装标识只在本地隔离测试显式开启时使用。
这是普通原生客户端的稳定标识绑定，不是硬件证明：改包、系统重置、克隆、用户配置或签名团队变化仍有边界。
Windows 重启、普通更新及 Android 同签名升级不会主动换标识；iOS Keychain 尚未经过本轮真机验证。
`security_events` 默认按 90 天窗口惰性清理；`account_ips` 记录账号出现过的 IP，当前保留至注销。
注销删除本人设备/IP映射，并清空对应安全事件中的 IP 与设备摘要；未匿名事件不等于永久保存。
管理端查询方式见[服务器与部署](服务器与部署.md)，没有将管理能力暴露为客户端 HTTP 接口。

- 只有随机挑战生成持久化待领宝箱；天梯、竞技场、关卡和好友切磋都没有战后宝箱（ssfight `rank.do` 只回积分/金杯/经验）。
- 随机挑战先固定四件奖品，领取前只给客户端票据；选箱后才返回翻牌内容。
- 选中的一件入账，其余三件只展示；旧的即时单件掉落已取消，避免同一份奖励重复发放。
- 断线重登后自动提示继续领取；重复点击、换位置重试及录像回放不会再次发奖。
- 天梯、竞技场、关卡、好友切磋按各自原有结算发奖，不叠加随机挑战的宝箱。
- 战斗中的三次手动飘物拾取已按服务端固定的 plan 恢复；奖池仍沿用单机复刻数据，不能视为原服概率完全还原。

## 6. 哪些部分没有完整还原

- 原版后端源码和完整公式不可得。伤害、概率及部分奖励使用本项目重建规则，不保证与原服完全一致。
- 当前是服务器计算的异步战斗，不是两名玩家同时操控的实时 PvP，也没有伪造“当前在线”对手。
- 征战沿用原版组队入口，但目前每名队员分别与满血首领战斗，尚未实现原版多人接力和共享首领血量；人少时等待到期可按已报名人数开战。离队或等待超时未开战时退还征战令。
- 征战获胜者获得经验，队伍最多获得一件战利品且不额外发金币，是联机版较保守的经济规则，并非原版奖励的完整复刻。
- 战后四选一的奖励由服务端持久化并只发放一次，奖池沿用单机复刻数据；原版服务器精确概率尚未核实，不能视为概率完全还原。
- 部分原版社交、师徒、运营活动和支付流程没有完整接入；有查询界面不代表原服全部流程已恢复。
- 留言板可查看最近 50 条服务器留言并回复。消息页论坛入口连接本服新建的论坛，支持帖子和回复；原版入口跳转外部九游论坛，本服论坛并非原外部网页的复刻。好友验证仍未开放；收徒（打对方或对方师父）、人机拜师与真人徒弟日供已接服务端。天梯战报支持按普通天梯规则再次挑战，并非复刻原服专门的复仇结算。
- 经典设置、登录及账号弹窗有自建部分，不能把“使用原素材”理解成原版每一页都完全相同。
- 设备摘要与 IP 审计不能阻止所有改包或跨账号作弊，也没有经过压测证明的容量承诺。
- `combatRetentionDays` 目前是配置项，尚不能据此宣称所有服务器回放会自动按天清理。
- 回放、审计日志与未领奖票据的存储保留需要分别维护，不能统一理解为只保留最近 50 条。

## 7. 当前部署与传输方式

正式可用入口是 `http://111.229.39.217`；线上已要求设备请求头并拒绝浏览器弱标识，服务器 API 与本地安装资源分离。
用户已明确接受当前 HTTP 传输方式及其明文风险，本说明不再要求开启无法控制的 443 安全组。
客户端保留 HTTP/HTTPS 探测；配置来源为 `src-tauri/online-api.json`，不把服务器管理凭据打入安装包。
服务器数据目录为 `/var/lib/ssdz`，代码更新应保留该目录；源码与数据库备份是两件不同的事。
运维地址、服务单元及现有部署细节见[服务器与部署](服务器与部署.md)。
更早的架构取证见[联机实现方案](联机实现方案.md)，其中以服务器权威章节及实际代码为准。

## 8. 安装包与 iOS 当前状态

Windows 构建入口是 `node tools/build-online-app.cjs`，目标为根目录的 `squirrel_fight_online.exe`。
Android 构建入口是 `node tools/build-online-apk.cjs`，安装包保存在 `src-tauri/dist/`。
本轮 APK 为 `squirrel_fight_online-1.0.2-arm64.apk`；与 1.0.1 同签名、版本码 1000002、SDK24+、arm64、v1/v2/v3 及 16 KB 对齐均通过检查。
Windows 原生标识两次读取稳定，最终 EXE 已隔离配置启动；Android 桥已编译并检查 APK 内 DEX/注解，没有新增权限，尚未真机安装回归。
iOS 入口是 `node tools/build-online-ios.cjs`；`--dry-run` 查看版本与输出计划，`--check` 检查配对 Mac。
iOS 只上传隔离的客户端源快照，不覆盖 Mac 单机工作树，不上传服务器、存档、同步令牌或签名私钥。
本轮静态检查确认版本为 1.0.2；Mac 的 `/api/ios-build/check` 最近一次检查返回 404，因此尚未生成 IPA。
Mac 接收端需运行 `node scripts/sync/sync.js restart` 重新加载已有构建接口，然后才能实际构建与回传。
计划产物是 `squirrel_fight_online_1.0.2_ios[_legacy]_unsigned.ipa`，未签名包仍需有效的安装签名。
iOS 为已授权 HTTP 模式设置仅针对 WKWebView 内容的 ATS 例外，没有全网络放开。
EXE、APK 与 IPA 是否完成、是否经过真实设备验证，应分别核对，不能以配置文件存在代替出包成功。
